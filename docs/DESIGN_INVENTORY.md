# 钢铁之门 · 设计盘点与概念收敛清单

版本：v0.12.31  
用途：把当前实现中的所有主要数据、参数、机制、界面与存档概念整理成一份可讨论的“设计底图”，并标出重复、分散、命名冲突和可统一的部分。  
声明：本文是盘点，不是平衡改动提案。所有数值以当前代码为准；“建议”部分只描述可以如何收敛，不直接改玩法。

## 0.0 已拍板并落地的设计决定（2026-11-08）

1. **分数拆分**：`score` = 可花费分数，`scoreEarned` = 累计分数；排行榜使用累计分数。
2. **黄圈经验**：`yellowXp` 独立累计用于黄圈胜负/指标，同时同步提供连队经验。
3. **BOSS 奖励**：统一奖励抽卡次数，不再掉落单位。
4. **卡包**：保留“即抽即开”。
5. **穿甲**：AP 不足无法击穿；溢出提高伤害；直射武器按溢出概率触发致命一击。
6. **雷达**：每轮扫描3圈/60秒，扫描角30°，点亮8秒，最后位置保留1分钟。
7. **舰船出生**：有己方港口时从港口近岸生成；否则从地图边缘、离岸≥500m、尽量远离敌军处生成。
8. **AI 舰船**：所有模式至少需要1座通讯塔；对抗模式花分数，背水一战按波次检测。
9. **普通空袭**：与 B-17 的500lb航弹共用数据。
10. **工程车**：地雷点击后3秒读条；铁丝网/拒马满值约1500m/1000m；可构筑/强化工事。

# 1. 对局核心概念

一局游戏（Run）包含：

1. 选择模式、地图、难度。
2. 蓝方玩家获得基础连队。
3. 通过击杀、占点、黄圈获得经验/分数。
4. 升级获得抽卡机会，抽卡获得单位、装备、工事、支援。
5. 用分数购买抽卡/单位/舰船/轰炸机等。
6. 通过黄圈经验、坚守时间或主动结算结束对局。
7. 上传公共排行榜。

核心资源有六类，但界面都叫“分/经验/卡”，这是后续最需要统一的命名区。

## 6.2 命中公式（当前实现）

```text
命中率 = 武器命中 × 距离衰减 × 移动惩罚 × 闪避修正
移动：×0.50
急行军：×0.50
闪避修正 = 1 - clamp(目标闪避 × (0.2 + 0.8 × 距离/射程), 0, 0.9)
```

`SL.ACCURACY_FALLOFF = 0.30` 是距离衰减参数。

## 6.3 伤害公式

```text
命中率 = 武器命中 × 距离衰减 × 移动惩罚 × 闪避修正
移动：×0.50
急行军：×0.50
闪避修正 = 1 - clamp(目标闪避 × (0.2 + 0.8 × 距离/射程), 0, 0.9)
```

穿甲/装甲：

```text
装甲等级 = target.def.armor（0~4）
需求 AP = [0, 0.35, 1.15, 1.6, 2.1][装甲等级]
AP < 需求：无法击穿，伤害为0
AP >= 需求：伤害 × (1 + min(0.60, 溢出AP × 0.30))
直射武器额外判定致命一击：
  概率 = min(0.40, 溢出AP × 0.18)
  伤害 × 2.5
```

- 致命一击仅对直射武器生效，炮弹/溅射不触发。
- 狙击对装甲使用 `armoredDmg/tankDmg/heavyDmg`，重坦无效。
- 炮火/空袭对工事走 `damageFortifications`，不是普通单位伤害。

**说明：** 地面单位现在使用统一穿甲/装甲等级；舰船仍使用单独的 `damageShip` 装甲公式，后续可继续收口。

# 7. 经验、升级、抽卡、卡牌

## 7.1 升级

- 初始升级需求：120 XP。
- 每级递增：70 XP。
- 蓝方经验倍率：2.5。
- 后追加成：每落后 1 级 +10%，上限 +100%（配置注释写 +150%，已漂移）。
- AI 经验：混战难度系数；防御模式 `SL.AI_XP_SCALE = 0.75`。
- 全灭奖励：200 XP。
- 重生等待：6 秒。

## 7.2 抽卡

- 升级：生成 5 张候选，选 1 张进手牌。
- 手牌上限：10。
- 购买抽卡：200 分起，每次 +20。
- 购买单位：200 分起，每次 +20，独立计数。
- `draftPick` 配置存在但未使用，当前固定选 1。
- BOSS 奖励已改为抽卡次数，不再直接发单位卡。
- 幽灵击杀也给抽卡次数。

### 动态敌人规模

```text
SL.AI_CAP_MULT = {
  easy: 0.8,
  normal: 1.0,
  hard: 1.2,
  endless: 1.2
}
```

- 每个 AI 阵营独立：上限 = 玩家存活单位 × 难度倍率
- 红绿互不共享上限，也会彼此交战
- 每 15 秒各自补员一次，每次最多 6 个
- 背水一战不补员
- AI 全灭重生以玩家开局 6 单位为参考，每个阵营按自己的倍率重生，再补员到上限

## 9.2 工事武器

| 类型 | 血量 | 弹药 | 射程 | 伤害/间隔 | 备注 |
|---|---:|---:|---:|---|---|
| 机枪碉堡 | 2000 | 400 | 300 | 12 / 0.12s | 对工事内步兵伤害×0.25 |
| 迫击炮阵地 | 1750 | 72 | 500 | 3管 / 0.45s间隔 / 90溅射 | 散布50 |

| 88防空炮阵地 | 2100 | 80 | 对地400 / 对空600 | 150 / 5s | — |

工事承伤与修复规则：

1. 所有伤害统一扣除工事区 `z.hp`，不单独扣武器血量。
2. 工事区归零时：
   - 生成工事区残骸 `z.rubble`；
   - 所有武器保留在 `z.structures[]`，但 `hp=0, destroyed=true`；
   - 不删除武器。
3. 修复顺序：
   - 先修复工事区本体，消耗30工程值，恢复 `z.hp` 和 `z.fortified`；
   - 工事区恢复后，武器仍是残骸状态；
   - 工兵/工程车逐一修复武器，每次只修一座；
   - 每座武器按自身 `maxHp` 判定修复资源，约为 `maxHp / 100` 工程值：
     - 机枪碉堡20
     - 迫击炮阵地18
     - 反坦克炮阵地19
     - 88炮阵地21
   - 修复完成后恢复满血，并补充部分弹药。

因此：

```text
工事区被摧毁 = 工事区残骸 + 所有武器残骸
修复 = 工事区本体 → 武器1 → 武器2 → ...
```

补给圈规则：

- 工事区未摧毁时，可被补给圈恢复 `z.hp`。
- 工事区已被摧毁时，补给圈不能修复；只能由工兵/工程车修复工事区。
- 工事区修复后，内部武器仍是残骸；补给圈可逐一恢复武器残骸。
- 武器修复同样按自身 `maxHp` 决定修复时间。

**当前技术冗余（保留，后续可清理）：**

- `z.structure` 是首座工事的别名。
- `z.rubble / z.rubbles / z.rubbleProgress` 是旧残骸系统；现在主要用于工事区级残骸。
- `z.hp/maxHp` 是工事区血量，`z.siteHp` 是站点初始血量。

# 18. 概念收敛建议

## A. 模式与难度：建立唯一注册表

**现状：** `mode === ...`、`isMeleeLike()`、`(lastStand || navalLastStand)` 散落 20+ 处；难度在防御表、混战表、API权重、UI名之间重复。

**建议：**

```text
SL.MODES[id] = {
  name, family: 'melee' | 'defense',
  naval: boolean,
  maps: [...],
  victory: { type: 'yellowXp' | 'holdTime', ... },
  playerScoreMult, ...
}
SL.DIFFICULTIES[id] = {
  name, weight,
  defense: { holdTime, waveAdd, waveScale },
  ai: { enemyXp, enemyDamage, aggro, caps, gaps, equip }
}
```

收益：

- 不再到处写模式字符串。
- 榜单权重与游戏内难度同源。
- 模式选择、UI 名称、结算、API 共用一份。
- 新玩法只加配置，不改条件分支。

## B. 可见性/接触：统一为 Contact

**现状：** 至少 10 个可见性字段/方法。

**建议：**

```text
Contact {
  entityId,
  side,
  visible: bool,
  litUntil,
  lastSeenAt,
  lastX, lastY,
  source: 'unit'|'radar'|'recon'|'seaplane'|'exposed'
}
```

雷达只写入 `Contact`，小地图只读 `Contact`，AI 只读 `Contact`。  
`lastKnown` 是 `Contact.lastX/lastY`，不再单独一套。

## C. 雷达：单一状态机

**现状：** 8 个并行字段。

**建议：**

```text
radar[side] = {
  phase: 'idle' | 'scanning' | 'cooling',
  phaseEnd,
  angle,
  progress,
  contacts: {}
}
```

UI 只读 `phase/progress/cooldown`；AI 只读 `contacts`。

## D. 奖励：每个实体自己声明

**现状：** `SL.REWARD` 缺项，回退到步兵；BOSS/飞机/幽灵各有硬编码奖励。

**建议：**

- 每个 `UNIT_TYPES[x]` 增加 `reward:{xp,score}`。
- 每个 BOSS/飞机有自己的 `reward`。
- `kill()` 只读取 `target.def.reward`，不再按类型表查。
- 抽卡次数作为统一 `draftChance` 奖励类型。

## E. 护甲/穿透：统一等级

**现状：** `armor` 数值在地面只当真假，重坦靠类型免疫；舰船用另一套公式。

**建议：**

```text
armorClass: none | light | medium | heavy | ship
penetration: 0..4
```

伤害统一为 `penetration - armorClass` 的减伤/免疫；删除“重坦类型免疫”特判。这样坦克、舰船、工事、BOSS 可以共享解释。

## F. 枪支/武器：统一字段

**现状：** `unit.range`、`weapon.range`、`aaRange`、`minRange`、`antiArmorRange`、`sniper` 特判、`noRangeBonus`、`requiresStop` 混用。

**建议：**

- 所有武器统一 `range/minRange/accuracy/penetration/projectile/splash/ammo/mag/reload/requiresStop`。
- 对空/对地用一个 `targetMask`。
- 反装甲用 `bonusVs`，不再写 `if type ===`。
- 单位默认武器引用 `weaponId`。

## G. 卡牌/抽卡/经济：拆成三层

**现状：** 卡牌定义、卡包、抽卡队列、舰船卡、B-17 面板、直接部署混在一起。

**建议：**

1. `Reward`：经验、分数、抽卡次数、单位、装备。
2. `DrawTable`：抽卡候选池。
3. `Card`：手牌/直接使用/部署。
4. `Purchase`：分数换抽卡、单位、舰船、B-17。

删除“包卡定义存在于 CARD_DEFS、抽到后立即 resolve”的双层结构。  
删除 `buyDraft` 与 `buyUnitReinforcement` 的价格重复。

## H. 工事：单层结构

**现状：** `structures[]` + `structure` + `rubble/rubbles/rubbleProgress` + `zone.hp` + `siteHp`。

**建议：**

```text
zone.fortification = {
  hp, maxHp,
  structures: [{ type, hp, maxHp, ammo, maxAmmo, state:'active'|'destroyed' }]
}
```

残骸只是 `structure.state='destroyed'`，修复直接改状态；区域被毁才产生 zone rubble。删除旧 `z.rubble` 分支。

## I. AI：按“玩家画像”统一

**现状：** AI 难度、波次、装备、工事、空军、海军各有独立表，且模式特判。

**建议：**

```text
AI_PROFILE[difficulty][mode] = {
  xpScale, damage, aggro, caps, reinforceGap,
  equipChance, equipMax, fortChance, air, navy
}
```

所有 AI 生成/升级/购买只读一份 profile。

## J. 空中单位：统一 AirEntity

**现状：** `planes`、`seaplanes`、`battleships`、`supplyShips`、`bombers` 分属不同数组；`kind` 字符串散落。

**建议：**

- 统一 `air` 实体：`role: airstrike|fighter|recon|supply|bomber|seaplane|hell`
- 统一 `bombSpec`、`mgSpec`、`flightProfile`。
- B-17 是玩家资产，但可复用同一种“飞机”渲染/伤害/奖励接口。

## K. 地图/站点：合并到 zone

**现状：** `T.navalSites.towers/radar/coastBases/ports` 与 `T.zones` 重复引用。

**建议：**

- 所有站点都是 `T.zones` 的一种 `kind`。
- `T.navalSites` 只作为查询索引，不存独立对象。
- 地图尺寸统一使用 `T.size`；删除固定 `mapSize` 假设。

## L. 榜单/存档：统一 RunRecord

**现状：** 当前 payload、近期记录、API row、UI row 四套字段映射；版本硬编码。

**建议：**

```text
RunRecord {
  runId, playerId, nickname, mode, difficulty, mapId,
  result, score, yellowXp, kills, losses,
  durationSec, wave, holdSec, shipsSunk, bossKills,
  endedAt, uploaded
}
```

当前、近期、上传、榜单共用。版本从 `version.txt` 或构建注入。

# 20. 已拍板的设计决定

1. 分数拆分为**花费分数**与**累计分数**；排行榜用累计分数。
2. 黄圈经验独立累计，同时同步提供连队经验。
3. BOSS 只奖励抽卡次数，不再掉落单位。
4. 卡包保留“即抽即开”。
5. 地面穿甲统一为装甲等级 + 穿透等级；不足免疫，溢出增伤；直射武器按溢出概率触发致命一击；100mm以上火炮直击强制穿甲。
6. 雷达扫描参与实际目标获取。
7. 最后出现位置保留1分钟。
8. 舰船可从己方港口近岸生成；无港口时从地图边缘、离岸≥500m、远离敌军处生成。背水一战 AI 舰船按波次检测，无塔则错过本次。
9. 普通空袭与 B-17 的500lb航弹共用数据。
10. AI 召唤舰船在所有模式都需要至少1座通讯塔。

# 21. 结论

当前设计不是“没有体系”，而是**体系分层没有收口**：

- 战斗逻辑在 `game.js` 里持续扩张；
- 参数一部分进 `config.js`，一部分留在运行时；
- 模式、难度、奖励、可见性、卡牌、AI 各自有局部规则；
- UI 为了适应历史功能，保留了很多同义字段和同义名称。

最值得优先统一的五个概念是：

```text
Mode / Difficulty
Reward
Contact / Vision
Fortification
Draw / Card / Purchase
```

这五个概念一旦收口，后续加单位、加模式、做 3D 渲染、做地图编辑器，都会明显更省力。
